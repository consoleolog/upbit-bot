## 1. 개요

**컨셉: "이보다 더 떨어질 수는 없다"는 시점에 사서, 조금 오르면 바로 팔기를 여러 번 반복해 작은 수익을 꾸준히 쌓습니다.** 한 번에 크게 버는 것이 아니라, 작은 수익을 자주 확정하고 손실은 작게 끊어 오래 살아남는 것이 목표입니다.

RSI, 스토캐스틱, MACD 3종의 신호를 조합해 **과매도 구간에서 반등이 확인되면 매수**하고, **목표 수익에 닿으면 바로 매도**합니다. 수익이 났다가 사라지려 하거나, 오래 오르지 않거나, 손절 기준에 닿아도 매도합니다.

| 항목 | 내용 |
|------|------|
| 캔들 | `timeframe` 단위 (예: 30분봉) |
| 지표 | MACD 3종, RSI, 스토캐스틱 slow. 기간은 `indicator` 설정 |
| 신호 | 지표 이벤트(과매수/과매도 진입, 골든/데드 크로스)가 발생하면 마지막 상태를 저장하고, 저장된 상태로 판단 |
| 신규 매수 | 잔고와 손절 폭으로 계산한 금액 (리스크 기반, 상한 있음). 포지션당 매수는 1회이며 추가 매수는 하지 않음 |
| 매도 | 보유 수량 전량. 익절, 수익 보호, 보유 기간 초과, 신호 매도, 손절 ([5.1](#51-판단-순서)) |
| 익절 | 순수익률이 포지션의 익절 목표 이상. 목표는 진입 시 변동성(ATR)으로 계산 |
| 손절 | 순수익률이 포지션의 손절 기준 이하. 손절 폭은 진입 시 변동성(ATR)으로 계산 |
| 전체 한도 | 동시 보유 포지션 수, 전체 노출, 일일 손실 한도 ([6.5](#65-전체-한도)) |
| 수수료율, 최소 주문 금액 | 거래소에서 마켓별로 확인 (설정 값 아님) |

### 1.1 판단 시점

| 판단 | 시점 | 기준 가격 |
|------|------|-----------|
| 신호 상태 갱신 | 캔들이 마감될 때마다 | 마감 캔들 |
| 신호 매도, 매수 | **가장 최근에 마감된 캔들**에서만 | 그 캔들의 종가 |
| 손절, 익절, 수익 보호 | 실시간 + 캔들 마감 직후 | 실시간 현재가 / 마감 캔들 종가 |
| 보유 기간 초과 | 캔들 마감 직후 | 마감 캔들 종가 |

- 신호에 기반한 판단은 **마감된 캔들로만** 합니다. 진행 중인 캔들의 지표 값은 가격에 따라 계속 바뀌어, 생겼다 사라지는 신호가 저장되기 때문입니다.
- 손절, 익절, 수익 보호는 신호가 아니라 가격 기준이므로 캔들 마감을 기다리지 않습니다. 조금 오른 순간을 놓치지 않기 위해서입니다.
- 놓친 캔들(서버가 멈춰 있던 동안의 캔들 등)은 신호 상태만 갱신하고, 그 캔들을 기준으로 사고팔지 않습니다. ([4.1](#41-이벤트))
- 이 문서의 기간·기준 값은 고정값이 아니라 [설정](#2-설정) 값입니다. 숫자로 적은 예시는 [2.1](#21-설정-예시)의 예시 값입니다.

## 2. 설정

### 2.1 설정 예시

```json
{
  "timeframe": "30m",
  "indicator": {
    "ema": { "short": 5, "mid": 8, "long": 13 },
    "macd_signal": 9,
    "rsi": { "period": 14, "signal": 9 },
    "stochastic": { "k_len": 14, "k_smooth": 3, "d_smooth": 4 }
  },
  "threshold": {
    "rsi": { "over_sold": 31, "over_bought": 60 },
    "stochastic": { "over_sold": 25, "over_bought": 75 },
    "stochastic_entry_max": 50
  },
  "order": {
    "risk_per_trade": 0.5,
    "max_position_ratio": 10.0,
    "slippage_rate": 3.0
  },
  "risk": {
    "max_open_positions": 3,
    "max_total_exposure": 30.0,
    "daily_loss_limit": 2.0
  },
  "exit": {
    "atr_period": 14,
    "atr_multiplier": 2.0,
    "min_stop_rate": 2.0,
    "max_stop_rate": 10.0,
    "min_atr_rate": 0.5,
    "take_profit_multiplier": 1.0,
    "min_take_profit_rate": 1.0,
    "protect_trigger_ratio": 0.6,
    "protect_floor_ratio": 0.3,
    "protect_min_gap": 0.3,
    "min_profit_rate": 0.5,
    "max_holding_candles": 10
  }
}
```

### 2.2 항목 설명

| 항목 | 예시 값 | 의미 |
|------|---------|------|
| `timeframe` | `30m` | 캔들 단위 |
| `indicator.ema` | 5 / 8 / 13 | MACD 계산에 쓰는 단기·중기·장기 EMA 기간 |
| `indicator.macd_signal` | 9 | MACD 시그널 기간 |
| `indicator.rsi` | 14 / 9 | RSI 기간, RSI 시그널 기간 |
| `indicator.stochastic` | 14 / 3 / 4 | %K 기간, slow %K 평활 기간, slow %D 평활 기간 |
| `threshold.rsi` | 31 / 60 | RSI 과매도 / 과매수 기준 |
| `threshold.stochastic` | 25 / 75 | 스토캐스틱 과매도 / 과매수 기준 (%K, %D 모두) |
| `threshold.stochastic_entry_max` | 50 | 신규 매수 시 현재 %K, %D가 이 값 이하여야 함 (반등 초기인지 확인) |
| `order.risk_per_trade` | 0.5 | 손절 시 잃어도 되는 금액의 비율 (호가 통화 주문 가능 잔고 대비, %) ([6.1](#61-매수-금액)) |
| `order.max_position_ratio` | 10.0 | 포지션 하나의 매수 금액 상한 (호가 통화 주문 가능 잔고 대비, %) |
| `order.slippage_rate` | 3.0 | 손절 매도가 판단 가격보다 불리하게 체결될 것으로 잡는 여유분 (%) |
| `risk.max_open_positions` | 3 | 같은 호가 통화에서 동시에 열어 둘 수 있는 포지션 수 ([6.5](#65-전체-한도)) |
| `risk.max_total_exposure` | 30.0 | 같은 호가 통화의 전체 노출 상한 (기준 자산 대비, %) |
| `risk.daily_loss_limit` | 2.0 | 같은 호가 통화의 하루 실현 손실 한도 (기준 자산 대비, %). 넘으면 신규 매수 중단 |
| `exit.atr_period` | 14 | 손절 폭 계산에 쓰는 ATR 기간 ([3.4](#34-atr)) |
| `exit.atr_multiplier` | 2.0 | 손절 폭 = ATR × 이 배수 |
| `exit.min_stop_rate` | 2.0 | 손절 폭 하한 (%). ATR이 작아도 이보다 좁게 잡지 않음 |
| `exit.max_stop_rate` | 10.0 | 손절 폭 상한 (%). ATR로 계산한 폭이 이보다 넓으면 매수하지 않음 |
| `exit.min_atr_rate` | 0.5 | 최소 변동성 (%). `ATR_rate`가 이보다 작으면 매수하지 않음 ([6.2](#62-주문-전-확인)) |
| `exit.take_profit_multiplier` | 1.0 | 익절 목표 = ATR × 이 배수 ([5.4](#54-익절)) |
| `exit.min_take_profit_rate` | 1.0 | 익절 목표 하한 (%). ATR이 작아도 이보다 낮게 잡지 않음 |
| `exit.protect_trigger_ratio` | 0.6 | 순수익률이 익절 목표의 이 비율에 닿은 적이 있으면 수익 보호를 시작 ([5.5](#55-수익-보호)) |
| `exit.protect_floor_ratio` | 0.3 | 수익 보호의 매도 기준을 익절 목표의 이 비율 이상으로 둠 |
| `exit.protect_min_gap` | 0.3 | 수익 보호의 시작 값과 매도 기준 사이의 최소 간격 (%p) |
| `exit.min_profit_rate` | 0.5 | 수익으로 볼 최소 순수익률 (%). 신호 매도의 조건이자 수익 보호 매도 기준의 하한 |
| `exit.max_holding_candles` | 10 | 보유 기간 상한 (캔들 수). 진입할 때 시간으로 바꿔 고정하고, 넘으면 손익과 관계없이 매도 ([5.6](#56-보유-기간-초과)) |

- 모든 항목은 바꿀 수 있는 값입니다. 표의 값은 예시이자 기본값입니다.
- 수수료율과 최소 주문 금액은 설정에 두지 않고 거래소에서 확인합니다. ([6.4](#64-거래소-주문-조건))

기본값의 근거 (보수적인 값을 선택)

| 항목 | 기본값 | 근거 |
|------|--------|------|
| `risk_per_trade` | 0.5% | 거래당 위험은 전통 시장에서 1~2%를 흔히 쓰지만, 변동성이 큰 암호화폐에서는 1% 또는 0.5%로 낮추는 것이 권장됨. 그중 가장 낮은 값 |
| `atr_period` | 14 | ATR 기간으로 가장 널리 쓰이는 값 |
| `atr_multiplier` | 2.0 | 추세를 따라가는 전략은 2~3.5배를 쓰지만, 반등(평균 회귀) 전략은 1~2배가 흔히 쓰임. 그중 넓은 쪽을 골라 작은 흔들림에 손절되는 것을 줄임. 리스크 기반 매수 금액([6.1](#61-매수-금액))이 손절 폭에 맞춰 줄어들어 손절 시 손실 금액은 같게 유지됨 |
| `take_profit_multiplier` | 1.0 | 반등 전략은 큰 목표를 노리지 않고 평균으로 돌아오는 만큼만 노리며, 목표를 2×ATR 이상으로 크게 잡으면 승률이 크게 떨어진다는 자료가 있음. "조금 오르면 판다"는 컨셉에 맞춰 1배 |
| `min_take_profit_rate` | 1.0% | 수수료와 일반적인 체결 가격 차이를 빼고도 수익이 남도록 하는 하한. 검증된 출처는 없고 보수적으로 정한 값 |
| `protect_trigger_ratio` | 0.6 | 수익 보호를 언제 시작할지는 정해진 값이 없고, 흔히 쓰는 "손절 폭만큼 오르면 본전으로 옮김"은 익절 목표가 손절 폭보다 작은 이 전략에서는 쓸 수 없음. 목표의 절반을 조금 넘은 지점으로 정함. 반등 전략은 진입 가격 근처로 자주 되돌아와, 보호를 너무 일찍 시작하면 수익 기회까지 줄어든다는 자료가 있어 절반보다 조금 높게 둠 |
| `min_profit_rate` | 0.5% | 시장가 매도의 체결 가격 차이를 덮어야 실제 수익이 남음. 주요 코인의 일반적인 체결 가격 차이 0.1~0.5% 중 상한 |
| `max_holding_candles` | 10 | 반등 전략에서 일정 기간 안에 반등하지 않으면 정리하는 규칙으로 5~10캔들이 제시됨. 반등할 시간을 주는 쪽인 10 |
| `min_stop_rate` | 2.0% | 손절 폭이 너무 좁으면 작은 흔들림에 손절되고, 매수 금액이 커짐. 검증된 출처는 없고 보수적으로 정한 값 |
| `max_stop_rate` | 10.0% | 기존 고정 손절 기준(-10%). 이보다 변동성이 크면 매수하지 않음 |
| `max_position_ratio` | 10% | 검증된 출처는 없음. 한 마켓에 잔고가 몰리지 않도록 보수적으로 정한 값 |
| `slippage_rate` | 3.0% | 시장가 주문의 체결 가격 차이는 미리 계산할 수 없음. 주요 코인은 0.1~0.5%, 유동성이 낮은 알트코인은 1~3%를 허용 범위로 드는 자료가 있어, 그 상한을 씀 |
| `max_open_positions` | 3 | 권장 수치를 제시한 출처는 없음. `max_position_ratio` 10% × 3 = 30%로 전체 노출 상한과 맞춤 |
| `max_total_exposure` | 30% | 위와 같음. 모든 포지션이 동시에 손절돼도 손실은 약 1.5% (+ 체결 가격 차이) |
| `daily_loss_limit` | 2.0% | 예시 설정들의 일일 손실 한도는 3~5%이고, 보수적 출발점으로 2~3%가 제시됨. 그중 낮은 값. 거래당 위험 0.5%의 4회분 |
| `min_atr_rate` | 0.5% | 다른 값에서 끌어낸 값. 익절 목표 하한(1.0%)이 ATR의 2배(`take_profit_multiplier`의 근거가 된 상한)를 넘지 않으려면 ATR이 0.5% 이상이어야 함. 이보다 변동성이 낮은 마켓은 반등 폭이 수수료와 체결 가격 차이를 덮기 어려움 |
| `protect_floor_ratio` | 0.3 | 검증된 출처는 없음. 익절 목표가 클수록 지키는 수익도 커지도록, 목표의 30%는 남기고 판다는 보수적인 값 |
| `protect_min_gap` | 0.3%p | 검증된 출처는 없음. 시작 값과 매도 기준이 너무 가까우면 작은 흔들림만으로 보호 매도가 일어나 평균 수익이 줄어듦. 주요 코인의 일반적인 체결 가격 차이(0.1~0.5%)의 중간 정도로 둠 |

- 체결 가격 차이를 두 가지로 씁니다. 매수 금액 계산의 `slippage_rate`(3%)는 **손절 때 가격이 급락하는 최악의 경우**에 대비한 값이고, `min_profit_rate`(0.5%)는 **평상시 매도**의 체결 가격 차이를 덮는 값입니다.

손익 구조 (기본값 기준)

| 항목 | 값 |
|------|----|
| 익절 폭 : 손절 폭 | ATR × 1.0 : ATR × 2.0 = 1 : 2 |
| 손익분기 승률 (가정) | 손절 폭 ÷ (익절 폭 + 손절 폭) ≈ **67%**. 모든 거래가 익절 목표나 손절선에서 끝난다고 **가정**한 값 |
| 실제 | 수익 보호, 보유 기간 초과, 신호 매도로 끝나는 거래는 목표보다 작게 벌거나 손절보다 작게 잃음. 수수료와 체결 가격 차이도 더해져 실제 손익분기 승률은 가정과 다름 |
| 의미 | 세 번 중 두 번 넘게 익절해야 수익. 익절을 자주 확정하고, 수익 보호와 보유 기간 상한으로 손절까지 가는 경우를 줄여 승률을 지키는 구조 |

- 이 값들은 백테스트로 검증한 값이 아닙니다.

### 2.3 설정 변경

| 항목 | 규칙 | 이유 |
|------|------|------|
| 적용 범위 | 설정은 **모든 마켓에 공통으로 하나**만 둡니다 | 점진적 개발 단계에서 단순하게 유지. 나중에 마켓별로 넓힐 수 있음 |
| 바꾸는 시점 | **재시작할 때만** 반영합니다. 실행 중에는 바꾸지 않습니다 | 실행 중에 바꾸면 처리 중인 캔들이 이전 설정과 새 설정으로 섞여 계산됨 |
| 지표 상태 | 시작할 때 설정이 직전 실행과 다르면, 모든 마켓의 신호 상태(`over_state`, `cross_state`)를 비웁니다. 지표 값은 새 설정으로 다시 계산하되, **신호는 재시작 이후에 마감되는 캔들에서만** 새로 판정합니다 | 저장된 신호는 이전 기간·기준으로 판정한 것이라 새 설정과 섞을 수 없음. 과거 캔들로 신호를 다시 만들면 오래전 이벤트로 신호가 바로 채워져, 설정을 바꾼 즉시 매수가 일어날 수 있음 |
| 열린 포지션 | 손절 폭, 익절 목표, 수익 보호 기준, 보유 기간 만료 시각, 최소 순수익률은 **진입할 때 정한 값을 그대로** 씁니다. 신호 매도의 신호 조건만 현재 설정의 신호 상태를 따릅니다 | 열린 포지션은 진입할 때 정한 기준으로 끝까지 판단합니다. 매수 금액이 진입 시의 손절 폭에 맞춰 계산되었고, 나머지도 같은 시점의 변동성과 캔들 단위로 정한 것이라 함께 고정함. 설정을 바꿔 캔들 단위가 달라져도 보유 기간이 늘거나 줄지 않고, 한 포지션에 서로 다른 최소 순수익률이 적용되지 않음 |

- 설정을 바꾼 직후에는 신호가 다시 쌓일 때까지 매수와 신호 매도가 일어나지 않습니다. 손절, 익절, 수익 보호, 보유 기간 초과는 신호를 쓰지 않으므로 바로 동작합니다.
- 진입 시 정한 값(손절 폭, 익절 목표, 수익 보호 기준, 보유 기간 만료 시각, 최소 순수익률)은 포지션과 함께 남깁니다. 재시작해도 바뀌지 않습니다.
- 지표 상태마다 어떤 설정으로 판정했는지 남겨, 설정이 바뀌었는지 알 수 있게 합니다.
- 전체 한도(`risk.*`)는 새로 여는 포지션에만 적용합니다. 한도를 낮춰도 이미 열린 포지션을 강제로 팔지는 않습니다.

## 3. 지표

모든 지표는 **마감된 캔들**의 값으로 계산합니다.

### 3.0 캔들 데이터

| 항목 | 규칙 | 이유 |
|------|------|------|
| 계산에 쓰는 캔들 수 | 판단할 캔들을 포함한 **최근 400개**의 마감 캔들 | EMA·RSI·ATR은 계산을 시작한 위치에 따라 초기 값이 달라짐. 측정해 보니 마지막 값이 시작 위치와 관계없이 같아지려면 최대 195개가 필요했고, 2배 여유를 둠 |
| 캔들이 400개 미만 | 그 마켓은 신호 갱신과 신규 매수를 하지 않음 | 값이 시작 위치에 따라 달라져, 같은 캔들로도 다른 신호가 나올 수 있음. 손절은 지표를 쓰지 않으므로 계속 동작 |
| 진행 중 캔들 | 쓰지 않음 | 마감된 캔들로만 판단 ([1.1](#11-판단-시점)) |
| 놓친 캔들 | 마지막으로 처리한 캔들 이후의 마감 캔들을 오래된 것부터 하나씩, 각 캔들 시점의 최근 400개로 처리 | 크로스를 놓치지 않기 위해 ([4.1](#41-이벤트)) |
| 빈 캔들 | 거래가 없던 시간대는 거래소에 캔들이 없음. 빠진 시각은 **직전 종가로 채운 캔들**(시가=고가=저가=종가=직전 종가, 거래량 0)로 메움 | 빈 시간대를 건너뛰면 시간상 떨어진 두 캔들 사이에서 크로스를 판정하게 됨 |
| 빈 캔들이 있는 마켓 | 최근 400개 중 채운 캔들이 **하나라도** 있으면 그 마켓은 신규 매수하지 않음 (신호 갱신과 매도는 계속) | 거래가 끊기는 마켓은 유동성이 낮아 체결 가격 차이가 크고, 채운 캔들로 계산한 지표는 실제 가격 움직임이 아님 |
| 이미 처리한 캔들의 값이 바뀜 | 그 캔들 직전의 신호 상태에서 시작해, 그 캔들부터 다시 신호를 판정 | 마감 직후 받은 값이 확정 전 값이었다면, 그 값으로 판정한 신호가 틀렸을 수 있음. 그 캔들로 이미 낸 주문은 되돌리지 않음 |
| 마감 직후 캔들이 아직 없음 | 잠시 뒤 다시 확인하고, 그래도 없으면 빈 캔들로 처리 | 마감 직후에는 거래소 캔들이 확정되지 않았을 수 있음 |

### 3.1 MACD 3종

| 이름 | 계산 | 예시 값 |
|------|------|---------|
| MACD short | EMA(close, `ema.short`) − EMA(close, `ema.mid`) | EMA(5) − EMA(8) |
| MACD mid | EMA(close, `ema.short`) − EMA(close, `ema.long`) | EMA(5) − EMA(13) |
| MACD long | EMA(close, `ema.mid`) − EMA(close, `ema.long`) | EMA(8) − EMA(13) |
| 시그널 | 각 MACD의 EMA(`macd_signal`) | EMA(9) |

- 설정 이름은 `indicator.` 아래 경로입니다. (예: `ema.short` = `indicator.ema.short`)
- EMA는 평활 계수 2 / (기간 + 1)의 지수이동평균이며, 첫 값은 처음 `기간`개 종가의 단순평균입니다.

### 3.2 RSI

Wilder 방식입니다. `period` = `rsi.period`, `signal_period` = `rsi.signal` (예시 14, 9)

```
AU = 상승폭의 Wilder 평균 (period), AD = 하락폭의 Wilder 평균 (period)
RSI    = 100 × AU / (AU + AD)
signal = EMA(RSI, signal_period)
```

| 경계 사례 | 값 |
|-----------|----|
| 상승만 있음 (AD = 0) | 100 |
| 계산 구간에 가격 변동이 전혀 없음 (AU = AD = 0) | **50** (과매도·과매수 어느 쪽도 아님) |

### 3.3 스토캐스틱 (slow)

`k_len` = `stochastic.k_len`, `k_smooth` = `stochastic.k_smooth`, `d_smooth` = `stochastic.d_smooth` (예시 14, 3, 4)

```
k_fast = (close − 최근 k_len개 최저가) / (최근 k_len개 최고가 − 최근 k_len개 최저가) × 100
k_slow = SMA(k_fast, k_smooth)     # slow %K
d_slow = SMA(k_slow, d_smooth)     # slow %D
```

| 경계 사례 | 처리 |
|-----------|------|
| 최근 `k_len`개 캔들의 최고가 = 최저가 | `k_fast`가 정의되지 않으므로, **그 캔들에서는 스토캐스틱 상태를 갱신하지 않음** |

### 3.4 ATR

손절 폭과 익절 목표 계산에만 씁니다. 신호 상태는 저장하지 않습니다. `n` = `exit.atr_period`

```
TR       = max(high − low, |high − 전 캔들 종가|, |low − 전 캔들 종가|)
ATR      = TR의 Wilder 평균 (n)
ATR_rate = ATR / close × 100        # 가격 대비 비율 (%)
```

- 매수 판단 시점의 마감 캔들로 계산합니다.

## 4. 신호 상태

### 4.1 이벤트

마감 캔들마다 아래 이벤트를 판정해 상태를 갱신합니다. 이벤트가 없으면 이전 상태가 유지됩니다.

| 지표 | 이벤트 | 조건 (마감 캔들 기준) | 저장되는 상태 |
|------|--------|-----------------------|---------------|
| RSI | 과매도 | RSI ≤ `threshold.rsi.over_sold` (예: 31) | `over_state = OVER_SOLD` |
| RSI | 과매수 | RSI ≥ `threshold.rsi.over_bought` (예: 60) | `over_state = OVER_BOUGHT` |
| RSI | 골든크로스 | RSI가 시그널을 아래→위로 교차 | `cross_state = GOLDEN_CROSS` |
| RSI | 데드크로스 | RSI가 시그널을 위→아래로 교차 | `cross_state = DEAD_CROSS` |
| 스토캐스틱 | 과매도 | %K, %D 모두 ≤ `threshold.stochastic.over_sold` (예: 25) | `over_state = OVER_SOLD` |
| 스토캐스틱 | 과매수 | %K, %D 모두 ≥ `threshold.stochastic.over_bought` (예: 75) | `over_state = OVER_BOUGHT` |
| 스토캐스틱 | 골든/데드크로스 | %K가 %D를 교차 | `cross_state` |
| MACD 3종 | 골든/데드크로스 | MACD가 시그널을 교차 | `cross_state` |

크로스 판정 (직전 캔들 `i-1`과 판단할 캔들 `i`, 메인선 `main`, 시그널선 `signal`)

| 이벤트 | 조건 |
|--------|------|
| 골든크로스 | `main[i-1] ≤ signal[i-1]` 그리고 `main[i] > signal[i]` |
| 데드크로스 | `main[i-1] ≥ signal[i-1]` 그리고 `main[i] < signal[i]` |

- `main[i] = signal[i]`(두 선이 정확히 같음)이면 이번 캔들에서는 크로스가 아닙니다. 다음 캔들에서 방향이 정해지면 그때 판정합니다.
- 비교할 값이 아직 계산되지 않았으면 그 지표는 이번 캔들에서 판정하지 않고 상태를 유지합니다.
- 과매수·과매도는 기준값과 **같아도** 진입으로 봅니다. (`≤`, `≥` 사용)
- 상태와 함께 이벤트가 발생한 캔들 시각(`over_time`, `cross_time`)을 저장합니다.
- 지표의 현재 값(`value`, `signal`)은 이벤트와 관계없이 매 캔들 갱신합니다.
- 마지막으로 처리한 캔들 이후의 마감 캔들은 **하나도 빠짐없이 순서대로** 처리합니다. 처리가 늦어져도 크로스를 놓치지 않습니다.
- 놓친 캔들을 처리할 때는 **신호 상태만 갱신**합니다. 매수·신호 매도 판단은 모두 처리한 뒤 가장 최근 캔들에서 한 번만 합니다. 지난 캔들의 가격으로 지금 사고팔지 않기 위해서입니다.

### 4.2 상태의 의미

마감 캔들을 빠짐없이 처리하므로 저장된 상태는 아래 뜻을 유지합니다. 상태에는 유효 기간을 두지 않습니다.

| 상태 | 의미 |
|------|------|
| `cross_state = GOLDEN_CROSS` | 지금 메인선이 시그널선 위에 있음 |
| `cross_state = DEAD_CROSS` | 지금 메인선이 시그널선 아래에 있음 |
| `over_state = OVER_SOLD` | 마지막으로 찍은 극단값이 과매도 |
| `over_state = OVER_BOUGHT` | 마지막으로 찍은 극단값이 과매수 |

- 크로스 상태는 오래전 크로스라도 그 뒤 반대 크로스가 없었다면 현재 상태와 같습니다.
- 과매도가 오래 이어지면 과매도 상태가 계속 유지되고, 과매수에 들어가면 상태가 바뀝니다.
- 상태가 지워지는 경우는 [상태 초기화](#7-상태-초기화)와 [설정 변경](#23-설정-변경)뿐입니다.

### 4.3 지표별 `value` / `signal`

| 지표 | `value` (메인선) | `signal` (시그널선) |
|------|------------------|---------------------|
| RSI | RSI | RSI 시그널 |
| 스토캐스틱 | slow %K | slow %D |
| MACD 3종 | MACD | MACD 시그널 |

## 5. 매매 판단

### 5.1 판단 순서

가장 최근 캔들이 마감된 직후 마켓마다 아래 순서로 판단합니다. 마켓당 주문은 한 번에 최대 1건입니다.

```
if 보유 중:
    if 손절 조건:             손절 → 종료
    if 익절 조건:             익절 → 종료
    if 수익 보호 조건:         수익 보호 매도 → 종료
    if 보유 기간 초과:         보유 기간 초과 매도 → 종료
    if 과매수 매도 조건:       매도 → 종료
    if 데드크로스 매도 조건:   매도 → 종료
else:
    if 신규 매수 조건:         신규 매수 → 종료
```

실시간(캔들 마감 사이)에는 가격 기준인 손절 → 익절 → 수익 보호만 같은 순서로 판단합니다.

- 보유 중에는 매도만 판단합니다. 추가 매수는 하지 않습니다.
- 손절을 가장 먼저 확인합니다. 손실을 막는 것이 수익을 확정하는 것보다 우선입니다.
- 해당 마켓에 체결이 끝나지 않은 주문이 있으면 판단하지 않습니다.

매매가 제한된 마켓

| 상태 | 신규 매수 | 익절·수익 보호·보유 기간 초과 | 신호 매도 | 손절 |
|------|-----------|-------------------------------|-----------|------|
| 매매 중단 (`halted`: 보유 수량 불일치, 손절 반복 실패) | 하지 않음 | **함** | 하지 않음 | **함** |
| 일일 손실 한도 도달 ([6.5](#65-전체-한도)) | 하지 않음 | 함 | 함 | 함 |
| 빈 캔들이 있음 ([3.0](#30-캔들-데이터)) | 하지 않음 | 함 | 함 | 함 |
| 캔들 400개 미만 ([3.0](#30-캔들-데이터)) | 하지 않음 | 함 (지표를 쓰지 않음) | 하지 않음 | 함 |

- 손절은 어떤 제한 상태에서도 막지 않습니다. 손실이 커지는 것을 막는 마지막 수단이기 때문입니다.
- `halted`에서도 **가격 기준 매도(손절, 익절, 수익 보호, 보유 기간 초과)는 모두** 합니다. 모두 위험을 줄이는 매도이고, 막으면 익절할 수 있던 포지션이 손실로 끝날 수 있기 때문입니다. 매도 수량은 기록상 보유 수량과 거래소의 실제 주문 가능 수량 중 작은 값입니다.
- `halted`에서 신호 매도를 막는 이유: 신호 상태를 믿고 판단하는 매도는 사람이 확인한 뒤 해도 됩니다.
- 매매 중단과 일일 손실 한도로 인한 중단은 **재시작해도 유지**되고, 사람이 확인한 뒤에만 풀립니다.

### 5.2 순수익률

보유 중인 포지션의 수익률은 매도 수수료까지 뺀 값입니다.

```
순수익률(%) = (기준 가격 × (1 − ask_fee) − 평단가) / 평단가 × 100
평단가     = (매수 체결 금액 합계 + 매수 수수료 합계) / 매수 체결 수량 합계
```

- 기준 가격: 실시간 손절은 현재가, 캔들 마감 직후 판단은 마감 캔들 종가
- 평단가는 체결 기준 가중평균이며 매수 수수료가 포함되어 있습니다.
- `ask_fee`는 매도 수수료율입니다. ([6.4](#64-거래소-주문-조건))

### 5.3 손절

| 사유 | 조건 |
|------|------|
| `STOP_LOSS` | 순수익률 ≤ −(포지션의 손절 폭) |

- 손절 폭은 진입할 때 [6.1](#61-매수-금액)에서 계산해 포지션과 함께 남긴 값입니다. 보유 중에는 바뀌지 않습니다.
- 실시간 현재가로 계속 확인하고, 캔들 마감 직후에도 마감 캔들 종가로 확인합니다.
- 조건을 충족하면 시장가로 전량 매도합니다.
- 실제 손실은 손절 폭보다 클 수 있습니다. 시장가 매도는 판단 가격보다 낮게 체결되고(체결 가격 차이), 가격이 급락하면 그 차이가 더 커집니다. 손절 폭과 [6.1](#61-매수-금액)의 손실 한도는 **보장이 아니라 목표**입니다.

**실시간 시세가 끊겼을 때** (익절, 수익 보호도 같음)

| 상황 | 처리 |
|------|------|
| 열린 포지션이 있는 마켓에서 **10초** 동안 새 시세가 없음 | 다른 경로로 현재가를 확인해 손절·익절·수익 보호를 판단하고, 시세가 다시 들어올 때까지 10초마다 반복 |

- 10초는 확인된 출처가 없어 보수적으로 정한 값입니다. 거래가 적은 마켓은 시세가 10초 넘게 없을 수 있지만, 확인 비용이 작아 그대로 둡니다.

**손절 주문이 실패했을 때**

| 실패 원인 | 처리 |
|-----------|------|
| 주문이 접수됐는지 알 수 없음 (응답 없음) | 같은 주문을 다시 내지 않음. 먼저 접수 여부를 확인하고, 접수되지 않았다고 확인되면 다시 판단 |
| 거래소 일시 오류 | 1초, 2초, 4초 간격으로 최대 3번 다시 주문. 모두 실패하면 "반복 실패" |
| 잔고 부족 | 실제 주문 가능 수량으로 줄여 한 번 다시 주문. 다시 실패하면 "반복 실패" |
| 최소 주문 금액 미달 | 남은 수량이 너무 작아 팔 수 없음. 포지션을 닫음 (남은 수량은 계좌에 그대로 둠) |
| 그 밖의 거절 | "반복 실패" |
| 반복 실패 | 마켓을 `halted`로 둠. `halted`에서도 손절은 계속 시도하므로, 다음 시세에서 조건이 맞으면 다시 주문 |

### 5.4 익절

| 사유 | 조건 |
|------|------|
| `TAKE_PROFIT` | 순수익률 ≥ 포지션의 익절 목표 |

```
take_profit_rate = max(ATR_rate × take_profit_multiplier, min_take_profit_rate)  (%)
```

- 익절 목표는 진입할 때 손절 폭과 같은 ATR로 계산해 포지션과 함께 남깁니다. 보유 중에는 바뀌지 않습니다.
- 실시간 현재가로 계속 확인하고, 캔들 마감 직후에도 마감 캔들 종가로 확인합니다.
- 조건을 충족하면 시장가로 전량 매도합니다. 목표에 닿은 순간 파는 것이 "조금 오르면 바로 판다"는 컨셉의 핵심입니다.
- 매도 주문이 실패했을 때의 처리는 손절과 같습니다([5.3](#53-손절)). 단, 반복 실패해도 `halted`로 두지는 않습니다. 익절 실패는 손실을 키우지 않고, 손절·수익 보호·보유 기간 초과가 계속 판단되기 때문입니다.

### 5.5 수익 보호

조금 오른 뒤 목표에 못 미치고 다시 내려오면 수익이 손실로 바뀝니다. 이를 막기 위해, 수익이 일정 수준을 넘은 적이 있으면 본전 근처로 내려왔을 때 팝니다.

| 사유 | 조건 |
|------|------|
| `PROFIT_PROTECT` | 보유 중 순수익률이 한 번이라도 **보호 시작 값** 이상이었음 **그리고** 지금 순수익률 ≤ **보호 매도 기준** |

```
보호 매도 기준 = max(min_profit_rate, take_profit_rate × protect_floor_ratio)        (%)
보호 시작 값   = max(take_profit_rate × protect_trigger_ratio, 보호 매도 기준 + protect_min_gap)  (%)
```

| 익절 목표 | 보호 매도 기준 | 보호 시작 값 |
|-----------|----------------|--------------|
| 1.0% | max(0.5, 0.3) = 0.5% | max(0.6, 0.8) = **0.8%** |
| 1.5% | max(0.5, 0.45) = 0.5% | max(0.9, 0.8) = 0.9% |
| 3.0% | max(0.5, 0.9) = **0.9%** | max(1.8, 1.2) = 1.8% |

- 시작 값과 매도 기준 사이를 최소 `protect_min_gap`만큼 벌려, 작은 흔들림만으로 보호 매도가 일어나지 않게 합니다.
- 익절 목표가 클수록 매도 기준도 올라가, 지키는 수익이 커집니다.
- 보호 시작 값이 익절 목표 이상이면(익절 목표가 매우 작은 경우) 그 포지션은 보호 없이 익절·손절·보유 기간만으로 판단합니다.
- 보호 기준은 진입할 때 계산해 포지션과 함께 남깁니다.
- 보유 중 가장 높았던 순수익률을 포지션과 함께 남깁니다. 재시작해도 보호 여부가 바뀌지 않게 하기 위해서입니다.
- 실시간 현재가로 계속 확인합니다.

### 5.6 보유 기간 초과

| 사유 | 조건 |
|------|------|
| `TIME_EXIT` | 지금 시각 ≥ 보유 기간 만료 시각 |

```
보유 기간 만료 시각 = 매수 체결 시각 + max_holding_candles × timeframe
```

- 만료 시각은 진입할 때 계산해 포지션과 함께 남깁니다. 보유 중에 `timeframe`이나 `max_holding_candles`를 바꿔도 이미 열린 포지션의 만료 시각은 바뀌지 않습니다.
- 손익과 관계없이 전량 매도합니다. 반등을 노리고 샀는데 정해진 기간 안에 오르지 않았다면 판단이 틀린 것으로 보고 정리합니다.
- 오래 횡보하는 포지션이 동시 보유 한도([6.5](#65-전체-한도))를 차지해 다음 매수를 막지 않게 하기 위해서입니다.
- 캔들 마감 직후에만 판단합니다. (만료 시각이 지난 뒤 처음 마감되는 캔들에서 매도)

### 5.7 신호 매도

앞의 매도 조건(손절, 익절, 수익 보호, 보유 기간 초과)에 해당하지 않을 때 확인합니다. 처음 충족된 조건으로 **전량 매도**합니다.

| 순서 | 사유 | 조건 |
|------|------|------|
| 1 | `OVERBOUGHT_EXIT` | 스토캐스틱 `over_state = OVER_BOUGHT` 그리고 RSI `over_state = OVER_BOUGHT` 그리고 순수익률 > `min_profit_rate` |
| 2 | `DEAD_CROSS_EXIT` | 스토캐스틱 `cross_state = DEAD_CROSS` 그리고 RSI `cross_state = DEAD_CROSS` 그리고 순수익률 > `min_profit_rate` |

- `min_profit_rate`는 포지션에 진입할 때의 값입니다. ([2.3](#23-설정-변경))
- 신호 매도는 순수익이 `min_profit_rate`보다 클 때만 합니다. 손실 상태의 매도는 손절과 보유 기간 초과로만 합니다.
- 과매수 상태는 반대 신호나 초기화 전까지 유지되므로([4.2](#42-상태의-의미)), `OVERBOUGHT_EXIT`는 "지금 과매수 구간에 있을 때"가 아니라 **"매수 이후 두 지표가 모두 과매수를 찍었고, 지금 순수익이 남아 있을 때"** 매도합니다. 가격이 과매수 구간에서 내려왔더라도 순수익이 남아 있으면 매도합니다.

| # | 조건 |
|---|------|
| 1 | RSI `over_state = OVER_SOLD` |
| 2 | RSI `cross_state = GOLDEN_CROSS` |
| 3 | 스토캐스틱 `over_state = OVER_SOLD` |

## 6. 주문 금액

금액은 모두 마켓의 호가 통화 단위입니다. (KRW 마켓이면 원, BTC 마켓이면 BTC)

### 6.1 매수 금액

**손절했을 때 잃는 금액이 잔고의 `risk_per_trade`를 넘지 않도록** 매수 금액을 정합니다(리스크 기반). 손절 폭이 넓으면(변동성이 크면) 매수 금액이 줄어듭니다.

```
available   = 호가 통화 주문 가능 잔고 − 같은 호가 통화의 미완료 매수 주문 금액 × (1 + bid_fee)
              ATR_rate < min_atr_rate 이면 매수하지 않음
stop_rate   = max(ATR_rate × atr_multiplier, min_stop_rate)  (%)
              stop_rate > max_stop_rate 이면 매수하지 않음

risk_budget = available × risk_per_trade / 100
amount      = risk_budget / (stop_rate / 100 + bid_fee + ask_fee + slippage_rate / 100)

amount      = min(amount,
                  available × max_position_ratio / 100,      # 포지션 상한
                  남은 전체 노출 한도 (6.5),                   # 전체 한도
                  available / (1 + bid_fee))                 # 수수료 포함 잔고 한도
amount      = 주문 금액 단위로 내림 (8.3)
```

- 손절 조건(순수익률)에는 이미 매수·매도 수수료가 들어 있지만, 분모에 수수료를 **한 번 더** 더해 매수 금액을 조금 더 작게 잡습니다. 보수적으로 두는 것입니다.
- `slippage_rate`를 더해, 손절이 판단 가격보다 불리하게 체결돼도 손실이 `risk_budget` 안에 들어오도록 **목표**합니다. 가격이 급락하면 넘을 수 있습니다. ([5.3](#53-손절))
- 계산한 `stop_rate`는 포지션의 손절 폭으로, 같은 ATR로 계산한 익절 목표([5.4](#54-익절))와 함께 남깁니다.
- 포지션당 매수는 1회입니다.

**동시 매수**

모든 마켓의 캔들이 같은 시각에 마감되므로, 여러 마켓이 동시에 매수하려 할 수 있습니다. 같은 잔고를 함께 보고 판단하면 잔고·한도 확인을 모두 통과해 한도를 넘게 됩니다.

| 규칙 | 내용 |
|------|------|
| 호가 통화별 매수 순서 | 같은 호가 통화(KRW, BTC, USDT)의 매수는 **하나씩** 처리합니다. 앞선 매수의 금액 계산부터 주문 접수까지 끝나야 다음 마켓의 매수를 판단합니다 |
| 미완료 매수 주문 | 아직 체결되지 않은 매수 주문 금액은 `available`에서 빼고, 전체 노출([6.5](#65-전체-한도))에 더합니다 |

예시 (KRW 마켓, `available` = 1,000,000원, 열린 포지션 없음, `ATR_rate` = 1.5%, 수수료 매수·매도 각 0.05%)

| 단계 | 값 |
|------|----|
| `stop_rate` | max(1.5 × 2.0, 2.0) = 3.0% (상한 10% 이내) |
| `take_profit_rate` | max(1.5 × 1.0, 1.0) = 1.5% |
| `risk_budget` | 1,000,000 × 0.5% = 5,000원 |
| 리스크 기반 금액 | 5,000 / (0.03 + 0.0005 + 0.0005 + 0.03) ≈ 81,967원 |
| 포지션 상한 | 1,000,000 × 10% = 100,000원 |
| 남은 전체 노출 한도 | 1,000,000 × 30% − 0 = 300,000원 |
| 매수 금액 | **81,967원** (리스크 기반 금액이 가장 작음) |
| 익절 시 수익 | 매입금액(수수료 포함) 약 82,008원 × 1.5% ≈ 1,230원 (잔고의 약 0.12%) |
| 손절 시 손실 (목표) | 약 82,008원 × 3.0% ≈ 2,460원. 손절 시점 평가금액(약 79,548원)이 3% 불리하게 체결되면 약 2,386원이 더해져 약 4,846원 (≤ 5,000원) |

### 6.2 주문 전 확인

아래를 모두 통과해야 매수 주문을 냅니다. 하나라도 맞지 않으면 주문하지 않고, 신호 상태도 바뀌지 않습니다.

| 확인 | 조건 |
|------|------|
| 마켓 상태 | `halted`가 아니고, 일일 손실 한도에 도달하지 않음 ([5.1](#51-판단-순서)) |
| 캔들 데이터 | 마감 캔들 400개 이상, 그중 빈 캔들 없음 ([3.0](#30-캔들-데이터)) |
| 변동성 | `ATR_rate` ≥ `min_atr_rate` (변동성이 너무 낮으면 반등 폭이 비용을 덮기 어려움) |
| 손절 폭 | `stop_rate` ≤ `max_stop_rate` (변동성이 너무 높으면 손절 폭이 지나치게 넓어짐) |
| 전체 한도 | 동시 보유 포지션 수 < `max_open_positions`, 이번 매수를 더한 전체 노출 ≤ `max_total_exposure` ([6.5](#65-전체-한도)) |
| 거래소 주문 조건 | 이 마켓의 수수료율·최소 주문 금액을 확인함 ([6.4](#64-거래소-주문-조건)) |
| 잔고 | 주문 금액 × (1 + `bid_fee`) ≤ `available` |
| 최소 주문 금액 | 주문 금액 ≥ 매수 최소 주문 금액 |

### 6.3 매도 수량

- 포지션의 보유 수량 전량을 매도합니다. (매도 수량을 거래소의 실제 수량으로 제한할지는 [미결 항목](#82-매도-수량의-기준))
- 매도 후 남은 수량의 가치가 매도 최소 주문 금액 미만이면 포지션을 닫습니다.

### 6.4 거래소 주문 조건

수수료율과 최소 주문 금액은 설정이 아니라 거래소의 값을 마켓별로 확인해 씁니다.

| 값 | 쓰는 곳 |
|----|---------|
| 매수 수수료율 (`bid_fee`) | 매수 금액 계산, 잔고 확인 |
| 매도 수수료율 (`ask_fee`) | 순수익률, 매수 금액 계산 |
| 매수 최소 주문 금액 | 주문 전 확인 |
| 매도 최소 주문 금액 | 포지션 종료 판단 |

| 시점 | 동작 |
|------|------|
| 서버 시작 | 거래 대상 마켓 전체의 값을 확인 |
| 매수 직전 | 그 마켓의 값을 다시 확인해 최신 값으로 계산 |
| 확인 실패 (매수) | 그 마켓은 이번 매수를 하지 않음 |
| 확인 실패 (서버 시작, 열린 포지션이 있는 마켓) | 서버 시작을 중단. 매도 수수료율 없이 순수익률·손절을 판단하지 않음 |

- 실제로 낸 수수료는 체결 결과의 값을 씁니다. 확인한 수수료율은 판단에만 씁니다.

### 6.5 전체 한도

마켓 하나가 아니라 **같은 호가 통화 전체**에 거는 한도입니다. 호가 통화(KRW, BTC, USDT)마다 따로 계산합니다. 통화가 다르면 금액을 더할 수 없기 때문입니다.

```
기준 자산   = 호가 통화 주문 가능 잔고 + 열린 포지션 매입금액 합계 (수수료 포함)
전체 노출   = 열린 포지션 매입금액 합계 + 미완료 매수 주문 금액 합계
```

| 한도 | 조건 | 넘으면 |
|------|------|--------|
| 동시 보유 포지션 수 | 열린 포지션 수 + 미완료 신규 매수 수 < `max_open_positions` | 신규 매수하지 않음 |
| 전체 노출 | 전체 노출 + 이번 매수 금액 ≤ 기준 자산 × `max_total_exposure` / 100 | 남은 한도만큼만 매수. 남은 한도가 최소 주문 금액보다 작으면 매수하지 않음 |
| 일일 손실 | 오늘 닫힌 포지션 중 **손실이 난 포지션의 손실 합계** ≥ 오늘 처음 계산한 기준 자산 × `daily_loss_limit` / 100 | 그 호가 통화의 **모든 마켓에서 신규 매수를 중단**. 모든 매도는 계속 |

- "오늘"은 한국 시간(KST) 00:00부터입니다.
- 일일 손실은 손실이 난 포지션만 더합니다. 같은 날의 수익으로 손실을 상쇄하지 않아, 수익을 낸 뒤 손실이 이어져도 한도에서 멈춥니다.
- 일일 손실은 닫힌 포지션만 셉니다. 열린 포지션의 평가 손실은 손절로 따로 제한됩니다.
- 일일 손실 한도로 중단된 매수는 **사람이 확인한 뒤 해제**합니다. 날짜가 바뀌어도 자동으로 풀지 않고, 재시작해도 유지합니다. 같은 날 손실이 이어진 원인을 모른 채 다시 매수하지 않기 위해서입니다.

## 7. 상태 초기화

신호 상태(`over_state`, `cross_state`)를 비워, 다음 판단에 **새로 발생한 신호**만 쓰이게 합니다. 지표의 현재 값과 시각은 그대로 둡니다.

| 시점 | 초기화 대상 |
|------|-------------|
| 매수 체결 | RSI, 스토캐스틱, MACD 3종 |
| 매도 체결 (손절, 익절, 수익 보호, 보유 기간 초과, 신호 매도) | RSI, 스토캐스틱, MACD 3종 |
| MACD 3종이 모두 데드크로스 상태가 됨 | RSI, 스토캐스틱 |

- 매수·매도 초기화는 주문이 **체결된 뒤**에 합니다. 체결되지 않은 주문으로는 상태를 지우지 않습니다.
- 매도 후에는 모든 신호가 비워지므로, 다음 매수에는 새로운 바닥 신호(과매도, 골든크로스)가 다시 필요합니다. 같은 반등에 두 번 들어가지 않습니다.
- MACD 초기화는 마감 캔들을 처리한 뒤 3종의 `cross_state`가 모두 `DEAD_CROSS`이고, 그중 하나라도 이번 캔들에서 바뀌었을 때 실행합니다. MACD가 계속 데드크로스 상태인 동안 매 캔들 반복해서 초기화하지 않기 위해서입니다.

## 8. 미결 항목

정하기 전에는 해당 동작을 구현하지 않습니다.

### 8.1 보유 수량 대사 기준

봇이 기록한 보유 수량과 거래소 계좌의 실제 보유 수량이 다르면 해당 마켓의 매매를 멈춥니다(`halted`). 이때 무엇을 불일치로 볼지 정해야 합니다.

| 항목 | 선택지 | 제안 | 판단 기준 |
|------|--------|------|-----------|
| 실제 보유 수량 | 주문 가능 수량만 / 주문 가능 수량 + 주문에 묶인 수량 | 주문 가능 수량 + 주문에 묶인 수량 | 매도 주문을 걸면 그 수량이 주문에 묶이므로, 주문 가능 수량만 보면 정상도 부족으로 나옴 |
| 비교 단위 | 마켓별 / 통화별 합산 | 통화별 합산 | 계좌 잔고는 통화 단위라, `KRW-BTC`와 `USDT-BTC` 포지션은 BTC 하나로 합쳐 보임 |
| 불일치 방향 | 실제 = 봇 / 실제 ≥ 봇 | 실제 ≥ 봇 | 같은 계좌에서 직접 코인을 거래하면 "실제 = 봇"은 항상 불일치. 위험한 쪽은 "봇 > 실제" (없는 수량을 팔려다 손절이 실패) |
| 허용 오차 (봇 > 실제) | 수량 표시 단위 / 최소 주문 금액 | 수량 표시 단위 (`0.00000001`) | 조금이라도 부족하면 전량 매도 주문이 거부될 수 있음. 단, [8.2](#82-매도-수량의-기준)에서 매도 수량을 실제 수량으로 제한하면 완화 가능 |
| 대사 시점 | 시작 시 / 시작 시 + 캔들 마감 직전 | 시작 시 + 캔들 마감 직전 | 실행 중에 직접 거래한 경우도 잡기 위해 |
| 중단 해제 | 자동 / 수동 | 수동 (사람이 확인 후 해제) | 원인을 모른 채 자동으로 재개하면 같은 문제가 반복됨 |

먼저 확인할 것: **같은 업비트 계좌에서 봇 말고 직접 코인을 사고팔기도 하는지.** 이에 따라 "불일치 방향"이 정해집니다.

### 8.2 매도 수량의 기준

현재는 기록상 보유 수량 전량을 매도합니다([6.3](#63-매도-수량)). 실제 수량이 그보다 적으면 매도 주문이 잔고 부족으로 거부되어, 손절이 실행되지 않을 수 있습니다.

| 선택지 | 내용 |
|--------|------|
| 현재 방식 유지 | 기록상 보유 수량 전량 매도. 대사로 불일치를 미리 막는 것에 의존 |
| 제안 | 매도 직전 거래소의 주문 가능 수량을 확인하고, 기록상 보유 수량과 주문 가능 수량 중 작은 값을 매도. 차이가 있으면 대사 대상으로 표시 |

- `halted` 마켓의 손절과 손절 주문의 잔고 부족 재주문에는 이미 이 방식을 씁니다. ([5.1](#51-판단-순서), [5.3](#53-손절)) 여기서 정할 것은 정상 마켓의 매도에도 적용할지입니다.

보유 수량의 역할 구분 (정하더라도 바뀌지 않는 원칙)

| 출처 | 쓰는 곳 | 이유 |
|------|---------|------|
| 봇의 기록 | 매매 판단: 평단가, 수익률, 실시간 손절 | 봇이 산 몫과 이번 포지션의 수수료 포함 평단가는 거래소 계좌 정보로 알 수 없음 |
| 거래소 계좌 | 실제로 수량이 있어야 하는 순간: 대사, (제안 시) 매도 수량 결정 | 계좌에 실제로 있는 수량의 기준은 거래소 |

### 8.3 주문 금액 단위

[6.1](#61-매수-금액)의 매수 금액을 어떤 단위로 내림할지 정해야 합니다. 시장가 매수는 주문 금액(호가 통화)으로 주문합니다.

| 마켓 | 확인할 것 |
|------|-----------|
| KRW | 주문 금액의 최소 단위 (원 단위인지) |
| BTC, USDT | 주문 금액의 소수점 자릿수 |

- 확인하기 전에는 BTC·USDT 마켓에서 매수하지 않습니다. KRW 마켓은 원 단위로 내림합니다.
