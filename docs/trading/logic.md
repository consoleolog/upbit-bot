upbit-bot의 매매 로직을 정리한 문서입니다. **무엇을, 언제, 어떤 조건으로 사고파는지**만 다룹니다. 구현 방법은 설계 문서에서 다룹니다.

## 1. 개요

**컨셉: "이보다 더 떨어질 수는 없다"는 시점에 사서, 조금 오르면 바로 팔기를 여러 번 반복해 작은 수익을 꾸준히 쌓습니다.**

RSI, 스토캐스틱, MACD 3종의 신호를 조합해 **과매도 구간에서 반등이 확인되면 매수**하고, **익절 목표에 닿거나 과매수·하락 전환이 확인되면 수익 중일 때 매도**합니다. 손실이 손절 기준에 닿으면 바로 매도합니다.

| 항목 | 내용 |
|------|------|
| 마켓 | KRW 마켓 |
| 캔들 | `timeframe` 단위 (예: 30분봉) |
| 지표 | MACD 3종, RSI, 스토캐스틱 slow |
| 신호 | 지표 이벤트(과매수/과매도 진입, 골든/데드 크로스)가 발생하면 마지막 상태를 저장하고, 저장된 상태로 판단 |
| 매수 | 원화 주문 가능 잔고의 일정 비율. 포지션당 1회 (추가 매수 없음) |
| 매도 | 보유 수량 전량. 손절, 익절, 신호 매도 |

### 1.1 판단 시점

| 판단 | 시점 | 기준 가격 |
|------|------|-----------|
| 신호 상태 갱신 | 캔들이 마감될 때마다 | 마감 캔들 |
| 매수, 신호 매도 | 가장 최근에 마감된 캔들에서 | 그 캔들의 종가 |
| 손절, 익절 | 실시간 + 캔들 마감 직후 | 실시간 현재가 / 마감 캔들 종가 |

- 신호에 기반한 판단은 **마감된 캔들로만** 합니다. 진행 중인 캔들의 지표 값은 가격에 따라 계속 바뀌어, 생겼다 사라지는 신호가 저장되기 때문입니다.
- 손절과 익절은 가격 기준이므로 캔들 마감을 기다리지 않습니다.

## 2. 설정

### 2.1 설정 예시

```json
{
  "timeframe": "30m",
  "indicator": {
    "ema": { "short": 5, "mid": 8, "long": 13 },
    "macd_signal": 9,
    "rsi": { "period": 14, "signal": 9 },
    "stochastic": { "k_len": 14, "k_smooth": 3, "d_smooth": 4 }
  },
  "threshold": {
    "rsi": { "over_sold": 31, "over_bought": 60 },
    "stochastic": { "over_sold": 25, "over_bought": 75 },
    "stochastic_entry_max": 50
  },
  "order": {
    "buy_ratio": 10.0
  },
  "exit": {
    "take_profit_rate": 1.5,
    "stop_loss_rate": 3.0,
    "min_profit_rate": 0.5
  }
}
```

### 2.2 항목 설명

| 항목 | 예시 값 | 의미 |
|------|---------|------|
| `timeframe` | `30m` | 캔들 단위 |
| `indicator.ema` | 5 / 8 / 13 | MACD 계산에 쓰는 단기·중기·장기 EMA 기간 |
| `indicator.macd_signal` | 9 | MACD 시그널 기간 |
| `indicator.rsi` | 14 / 9 | RSI 기간, RSI 시그널 기간 |
| `indicator.stochastic` | 14 / 3 / 4 | %K 기간, slow %K 평활 기간, slow %D 평활 기간 |
| `threshold.rsi` | 31 / 60 | RSI 과매도 / 과매수 기준 |
| `threshold.stochastic` | 25 / 75 | 스토캐스틱 과매도 / 과매수 기준 (%K, %D 모두) |
| `threshold.stochastic_entry_max` | 50 | 신규 매수 시 현재 %K, %D가 이 값 이하여야 함 (반등 초기인지 확인) |
| `order.buy_ratio` | 10.0 | 매수 금액 = 원화 주문 가능 잔고 × 이 비율 (%). 0보다 크고 100보다 작아야 함 (수수료를 더해도 잔고를 넘지 않도록) |
| `exit.take_profit_rate` | 1.5 | 익절 목표 순수익률 (%) |
| `exit.stop_loss_rate` | 3.0 | 손절 기준 순수익률 (%). 순수익률이 −이 값 이하면 손절 |
| `exit.min_profit_rate` | 0.5 | 신호 매도를 허용하는 최소 순수익률 (%) |

- 모든 항목은 바꿀 수 있는 값입니다. 표의 값은 예시이자 기본값입니다.
- 기본값은 백테스트로 검증한 값이 아닙니다.
- 익절 1.5% : 손절 3.0%는 1 : 2입니다. "조금 오르면 판다"는 컨셉에 맞춰 익절을 작게 두고, 손절은 작은 흔들림에 걸리지 않을 만큼 둡니다.
- `min_profit_rate`는 시장가 매도의 체결 가격 차이를 덮을 만큼 둡니다. 순수익률이 0을 조금 넘는 정도면 실제로는 손실일 수 있기 때문입니다.

### 2.3 설정 변경

- 설정은 **재시작할 때만** 바꿉니다.
- 시작할 때 지표 설정(`indicator`, `threshold`, `timeframe`)이 직전 실행과 다르면, 모든 마켓의 신호 상태를 비우고 **재시작 이후에 마감되는 캔들에서만** 새로 판정합니다. 이전 설정으로 판정한 신호와 섞이지 않게 하기 위해서입니다.
- 열린 포지션의 익절·손절·최소 순수익률은 **매수할 때의 값**을 끝까지 씁니다. 보유 중에 설정을 바꿔도 그 포지션의 기준은 바뀌지 않습니다.

## 3. 지표

모든 지표는 **마감된 캔들**로 계산합니다.

### 3.0 캔들 데이터

| 항목 | 규칙 | 이유 |
|------|------|------|
| 계산에 쓰는 캔들 수 | 판단할 캔들을 포함한 **최근 200개**의 마감 캔들 (거래소에서 한 번에 받을 수 있는 최대 개수) | EMA·RSI는 계산을 시작한 위치에 따라 초기 값이 조금씩 달라짐. 200개면 그 차이가 RSI 기준 약 0.0001로, 측정한 9만 번의 판정에서 크로스 판정이 한 번도 달라지지 않음 |
| 계산 구간이 150개 미만 | 그 캔들에서는 신호를 갱신하지 않고, 매수하지 않음 | 150개보다 짧으면 초기 값 차이가 커져 같은 캔들로도 다른 신호가 나올 수 있음 |
| 놓친 캔들 50개 이하 | 받은 200개 안에서 마지막으로 처리한 캔들 이후의 마감 캔들을 오래된 것부터 하나씩 처리 | 서버가 멈춰 있던 동안의 크로스를 놓치지 않기 위해. 50개 이하면 각 캔들의 계산 구간이 150개 이상 유지됨 |
| 놓친 캔들 50개 초과 | 신호 상태를 비우고, 처리를 다시 시작한 뒤 마감되는 캔들부터 새로 판정 ([설정 변경](#23-설정-변경)과 같은 처리) | 오래 멈춰 있었다면 그 사이의 신호는 이미 지난 것이라 다시 만들지 않음. 30분봉 기준 약 하루 |

### 3.1 MACD 3종

| 이름 | 계산 | 예시 값 |
|------|------|---------|
| MACD short | EMA(close, `ema.short`) − EMA(close, `ema.mid`) | EMA(5) − EMA(8) |
| MACD mid | EMA(close, `ema.short`) − EMA(close, `ema.long`) | EMA(5) − EMA(13) |
| MACD long | EMA(close, `ema.mid`) − EMA(close, `ema.long`) | EMA(8) − EMA(13) |
| 시그널 | 각 MACD의 EMA(`macd_signal`) | EMA(9) |

- EMA는 평활 계수 2 / (기간 + 1)의 지수이동평균이며, 첫 값은 처음 `기간`개 종가의 단순평균입니다.

### 3.2 RSI

Wilder 방식입니다. `period` = `rsi.period`, `signal_period` = `rsi.signal` (예시 14, 9)

```
AU = 상승폭의 Wilder 평균 (period), AD = 하락폭의 Wilder 평균 (period)
RSI    = 100 × AU / (AU + AD)
signal = EMA(RSI, signal_period)
```

| 경계 사례 | 값 |
|-----------|----|
| 상승만 있음 (AD = 0) | 100 |
| 가격 변동이 전혀 없음 (AU = AD = 0) | 50 (과매도·과매수 어느 쪽도 아님) |

### 3.3 스토캐스틱 (slow)

`k_len`, `k_smooth`, `d_smooth` = `indicator.stochastic` (예시 14, 3, 4)

```
k_fast = (close − 최근 k_len개 최저가) / (최근 k_len개 최고가 − 최근 k_len개 최저가) × 100
k_slow = SMA(k_fast, k_smooth)     # slow %K
d_slow = SMA(k_slow, d_smooth)     # slow %D
```

| 경계 사례 | 처리 |
|-----------|------|
| 최근 `k_len`개 캔들의 최고가 = 최저가 | 그 캔들에서는 스토캐스틱 상태를 갱신하지 않음 |

## 4. 신호 상태

### 4.1 이벤트

마감 캔들마다 아래 이벤트를 판정해 상태를 갱신합니다. 이벤트가 없으면 이전 상태가 유지됩니다.

| 지표 | 이벤트 | 조건 | 저장되는 상태 |
|------|--------|------|---------------|
| RSI | 과매도 | RSI ≤ `threshold.rsi.over_sold` | `over_state = OVER_SOLD` |
| RSI | 과매수 | RSI ≥ `threshold.rsi.over_bought` | `over_state = OVER_BOUGHT` |
| RSI | 골든/데드크로스 | RSI가 시그널을 교차 | `cross_state` |
| 스토캐스틱 | 과매도 | %K, %D 모두 ≤ `threshold.stochastic.over_sold` | `over_state = OVER_SOLD` |
| 스토캐스틱 | 과매수 | %K, %D 모두 ≥ `threshold.stochastic.over_bought` | `over_state = OVER_BOUGHT` |
| 스토캐스틱 | 골든/데드크로스 | %K가 %D를 교차 | `cross_state` |
| MACD 3종 | 골든/데드크로스 | MACD가 시그널을 교차 | `cross_state` |

크로스 판정 (직전 캔들 `i-1`, 판단할 캔들 `i`)

| 이벤트 | 조건 |
|--------|------|
| 골든크로스 | `main[i-1] ≤ signal[i-1]` 그리고 `main[i] > signal[i]` |
| 데드크로스 | `main[i-1] ≥ signal[i-1]` 그리고 `main[i] < signal[i]` |

- 두 선이 정확히 같으면 이번 캔들에서는 크로스가 아닙니다.
- 상태와 함께 이벤트가 발생한 캔들 시각을 저장합니다.
- 놓친 캔들을 처리할 때는 **신호 상태만 갱신**합니다. 매수·신호 매도는 모두 처리한 뒤 가장 최근 캔들에서 한 번만 판단합니다.

### 4.2 상태의 의미

상태에는 유효 기간을 두지 않습니다.

| 상태 | 의미 |
|------|------|
| `cross_state = GOLDEN_CROSS` | 지금 메인선이 시그널선 위에 있음 |
| `cross_state = DEAD_CROSS` | 지금 메인선이 시그널선 아래에 있음 |
| `over_state = OVER_SOLD` | 마지막으로 찍은 극단값이 과매도 |
| `over_state = OVER_BOUGHT` | 마지막으로 찍은 극단값이 과매수 |

- 상태가 지워지는 경우는 [상태 초기화](#7-상태-초기화), [설정 변경](#23-설정-변경), 놓친 캔들이 50개를 넘었을 때([3.0](#30-캔들-데이터))뿐입니다.

## 5. 매매 판단

### 5.1 판단 순서

가장 최근 캔들이 마감된 직후 마켓마다 아래 순서로 판단합니다. 마켓당 주문은 한 번에 최대 1건입니다.

```
if 보유 중:
    if 손절 조건:             손절 → 종료
    if 익절 조건:             익절 → 종료
    if 과매수 매도 조건:       매도 → 종료
    if 데드크로스 매도 조건:   매도 → 종료
else:
    if 신규 매수 조건:         매수 → 종료
```

- 실시간(캔들 마감 사이)에는 손절 → 익절만 판단합니다.
- 해당 마켓에 체결이 끝나지 않은 주문이 있으면 판단하지 않습니다.
- 주문(매수, 매도 모두)의 응답을 받지 못하면 같은 주문을 다시 내지 않습니다. 먼저 거래소에 접수됐는지 확인하고, 접수되지 않았을 때만 다시 판단합니다. 같은 마켓을 두 번 사거나 두 번 파는 것을 막기 위해서입니다.

### 5.2 순수익률

수수료까지 뺀 수익률입니다.

```
순수익률(%) = (기준 가격 × (1 − 매도 수수료율) − 평단가) / 평단가 × 100
평단가     = (매수 체결 금액 + 매수 수수료) / 매수 체결 수량
```

- 기준 가격: 실시간 판단은 현재가, 캔들 마감 직후 판단은 마감 캔들 종가
- 평단가는 실제 체결 기준이며 매수 수수료가 포함되어 있습니다.
- 매도 수수료율은 거래소의 값을 씁니다.

### 5.3 손절

| 사유 | 조건 |
|------|------|
| `STOP_LOSS` | 순수익률 ≤ −`stop_loss_rate` |

- 시장가로 전량 매도합니다.
- 실제 손실은 손절 기준보다 클 수 있습니다. 시장가 매도는 판단 가격보다 낮게 체결되고, 가격이 급락하면 차이가 더 커집니다.

### 5.4 익절

| 사유 | 조건 |
|------|------|
| `TAKE_PROFIT` | 순수익률 ≥ `take_profit_rate` |

- 시장가로 전량 매도합니다. 목표에 닿은 순간 파는 것이 "조금 오르면 바로 판다"는 컨셉의 핵심입니다.

### 5.5 신호 매도

손절·익절에 해당하지 않을 때 확인합니다. 처음 충족된 조건으로 전량 매도합니다.

| 순서 | 사유 | 조건 |
|------|------|------|
| 1 | `OVERBOUGHT_EXIT` | 스토캐스틱 `over_state = OVER_BOUGHT` 그리고 RSI `over_state = OVER_BOUGHT` 그리고 순수익률 > `min_profit_rate` |
| 2 | `DEAD_CROSS_EXIT` | 스토캐스틱 `cross_state = DEAD_CROSS` 그리고 RSI `cross_state = DEAD_CROSS` 그리고 순수익률 > `min_profit_rate` |

- 신호 매도는 순수익일 때만 합니다. 손실 상태의 매도는 손절로만 합니다.

### 5.6 매수

**신규 매수 (미보유)**: 9개 모두 참

| # | 조건 |
|---|------|
| 1 | RSI `over_state = OVER_SOLD` |
| 2 | RSI `cross_state = GOLDEN_CROSS` |
| 3 | 스토캐스틱 `over_state = OVER_SOLD` |
| 4 | 스토캐스틱 `cross_state = GOLDEN_CROSS` |
| 5 | MACD short `cross_state = GOLDEN_CROSS` |
| 6 | MACD mid `cross_state = GOLDEN_CROSS` |
| 7 | MACD long `cross_state = GOLDEN_CROSS` |
| 8 | 스토캐스틱 현재 %D ≤ `threshold.stochastic_entry_max` |
| 9 | 스토캐스틱 현재 %K ≤ `threshold.stochastic_entry_max` |

조건이 모두 참이어도 [6. 주문 금액](#6-주문-금액)의 확인을 통과해야 주문합니다.

## 6. 주문 금액

### 6.1 매수

```
매수 금액 = 원화 주문 가능 잔고 × buy_ratio / 100   (원 단위로 내림)
```

| 항목 | 규칙 |
|------|------|
| 잔고 | 매수할 때마다 원화 주문 가능 잔고를 한 번 조회해 계산 |
| 최소 주문 금액 | 매수 금액 < 거래소 최소 주문 금액이면 매수하지 않음 |
| 동시 매수 | 같은 시각에 여러 마켓이 매수하면 **하나씩 차례로** 처리. 앞선 매수가 끝난 뒤 줄어든 잔고로 다음 금액을 계산 |

- 매수하지 않으면 신호 상태도 바뀌지 않습니다.
- 최소 주문 금액은 거래소의 값을 씁니다.
- 매수 금액이 잔고의 일부(`buy_ratio`)라서, 수수료를 더해도 잔고를 넘지 않습니다.
- 동시 매수를 차례로 처리하는 이유: 모든 마켓의 캔들이 같은 시각에 마감되므로, 같은 잔고를 함께 보고 계산하면 잔고보다 많이 사려다 주문이 거절될 수 있습니다.

## 7. 상태 초기화

신호 상태(`over_state`, `cross_state`)를 비워, 다음 판단에 **새로 발생한 신호**만 쓰이게 합니다. 지표의 현재 값은 그대로 둡니다.

| 시점 | 초기화 대상 |
|------|-------------|
| 매수 체결 | RSI, 스토캐스틱, MACD 3종 |
| 매도 체결 (손절, 익절, 신호 매도) | RSI, 스토캐스틱, MACD 3종 |
| MACD 3종이 모두 데드크로스 상태가 됨 | RSI, 스토캐스틱 |

- 매수·매도 초기화는 주문이 **체결된 뒤**에 합니다. 체결되지 않은 주문으로는 상태를 지우지 않습니다.
- 매도 후에는 모든 신호가 비워지므로, 다음 매수에는 새로운 바닥 신호가 다시 필요합니다.
- MACD 초기화는 3종이 모두 `DEAD_CROSS`이고, 그중 하나라도 이번 캔들에서 바뀌었을 때만 실행합니다. 데드크로스가 이어지는 동안 매 캔들 반복하지 않기 위해서입니다.

## 8. 기존 로직과 달라진 점

| 항목 | 기존 로직 | 1단계 | 고친 문제 |

| 신호 상태 | 메모리 | 저장, 재시작해도 유지 | 재시작하면 신호가 사라짐 |
| 놓친 캔들 | 처리하지 않음 | 순서대로 신호만 갱신 | 멈춘 동안의 크로스를 놓침 |
| 매수 금액 | 고정 10,000원 | 원화 잔고의 일정 비율 | 잔고가 바뀌어도 매수 금액이 그대로 |
| 추가 매수 | 2 × n배 금액으로 상한 없이 | 없음 | 하락장에서 투입 금액이 계속 커짐 |
| 손절 | 없음 (주석 처리) | 고정 % 손절, 실시간 | 손실이 무한정 커질 수 있음 |
| 익절 | 없음 | 고정 % 익절, 실시간 | 컨셉("조금 오르면 판다")에 맞는 매도가 없음 |
| 과매수 매도 | 손실이어도 매도 | 순수익일 때만 | 손실 상태에서 신호로 매도 |
| 수익률 | 수수료 미반영, 단순 평균 평단가 | 수수료 반영, 체결 기준 평단가 | 수익으로 판단했지만 실제로는 손실 |
| 상태 초기화 시점 | 주문 직후 | 체결 뒤 | 주문이 실패해도 신호가 지워짐 |
| 주문 결과 | 확인하지 않음 | 체결로 판단, 응답이 없으면 접수 여부 확인 | 실패한 주문을 성공으로 기록, 중복 주문 |
